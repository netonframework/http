# HTTP/3 review, 2026-09-29

Scope: HTTP/3 control framing, stateless QPACK decoding, request-body
accounting, client request creation, and the QUIC/TLS integration boundary.
This is not a full audit of HTTP/1, HTTP/2, WebSocket or QUIC cryptography.

## Correctness fixes

- Validate the first control-stream wire type before the generic decoder can
  skip unknown frames. Reject immediately with H3_MISSING_SETTINGS, including
  when the peer withholds the unknown frame's payload (RFC 9114 section 6.2.1).
- Reject a negative QPACK Base even when no dynamic references occur. Required
  Insert Count is zero in this implementation, so a set Sign bit is invalid
  (RFC 9204 section 4.5.1.2). Positive Base remains accepted.
- Apply Content-Length overflow checks while discarding body data for
  recvTrailers, not just at FIN/trailers. The error is stream-local.
- Keep ownership of an opened client stream until sendRequest returns its
  handle. Failure/cancellation resets the send half and stops the receive half.
  Recheck GOAWAY and sender closure after the suspending openBi call.

Tests cover control framing through both the memory and loopback QUIC adapters;
the latter still uses mock TLS. Client lifecycle tests use explicit suspension
barriers, not sleep-based races.

Validation: HTTP/3 macOS ARM64 suite passes 378 tests, none skipped. The five
new control-ordering/QPACK cases were first run against the original production
code and all failed. The previous QPACK test explicitly accepting negative Base
was corrected to test positive Base; the RFC forbids negative Base even without
dynamic references. Existing empty-FIN behavior for locally oversized request
headers is preserved while the abandoned receive half is now stopped.
The HTTP macOS ARM64 suite also completes: 1197 reported, 1183 passed,
14 skipped, zero failures/errors. Linux and Windows were not rerun in this review.

## Release gates still open

1. Implement and integrate real QUIC TLS, with certificate/hostname validation,
   ALPN, transport parameters, encryption-level transitions and alert mapping.
   CryptoSession currently has no explicit native-session release contract;
   define ownership and test cleanup on failed handshake and connection teardown
   before attaching an OpenSSL session. Cleaner-only release is not sufficient.
2. Run independent QUIC and HTTP/3 interoperability against external peers, not
   just two endpoints sharing this implementation and the mock handshake.
3. Exercise packet loss, reordering, cancellation, stream-credit exhaustion and
   connection shutdown across the integrated HTTP/3 path.
4. Audit remaining response semantics (informational responses and bodyless
   responses), stream split ownership and public API cancellation guarantees.
5. Validate target-platform execution separately from cross-compilation, and
   verify clean builds without unpublished mavenLocal artifacts.

Passing the existing test suite or the additional tests here does not establish
production readiness. HTTP/3 has substantial implementation, but QUIC/TLS and
end-to-end verification remain substantive work rather than final wiring.
